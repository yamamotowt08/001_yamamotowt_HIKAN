## 3. 1 回の変更の進め方(毎回この順で行う)

### 手順 1: 要望を受ける
- 文章だけで形が決まらない部材は、**手本の樋門設計ソフトの入力画面の写真**をもらう(記号・寸法線の位置がそのまま定義になる)。
- 写真は拡大して寸法の数値どうしの関係を確かめる(例: 操作台 X2 6.3 = 1.1 × 2 + 0.8 × 2 + 2.5)。

### 手順 2: 形・決め方を確認する(実装前に必ず)
- **文書に寸法・配置の規定が無い部材は、推測で作らない**。胸壁は推測で作って 3 回訂正になった。
- 読み方が複数あるときは、ASCII の図(断面・平面・側面)を付けた選択肢で確認する。推奨案を 1 つ示す。
- 確認する典型的な論点:
  - どの面・どの点を基準に測るか(例: 天端高は Z = 0 からか敷高からか)
  - 入力するか自動で決まるか(例: Y3 = H1 − 敷高、門柱の位置 = 胸壁のたて壁の背面)
  - 未実装の形式をどう見せるか(これまでは「灰色で表示だけ」)
  - 既存図面(旧 XData)をどう読むか(これまでは「キーが無ければ設置しない」)

### 手順 3: Core を実装する(`src/Hikan.Core`)
- 部材は**直方体(`HikanPart`)**、翼壁は**台形断面の部材(`HikanTaperedPart`)**、ハンチは**多角形断面の柱(`HikanPrismPart`)**で表す。
- 部材には区分(`Member`)を付け、重なりをどの部材の数量から引くかを決める(先に作る部材が持つ: 函体 → 胸壁 → 門柱 …)。
- 体積は「直方体の和 − 内空 − 直方体どうしの重なり(対ごと)+ 翼壁 − 翼壁との重なり + ハンチ」。
  **3 個以上の部材が同じ点で重ならない**ことを整合性チェック(`HikanValidator`)で保証する。
- 整合性チェックの文は「`<部材名>の<項目>`」で書き始める(入力画面が該当欄を探すのに使う)。
- XData のキーを足したら、旧図面(キー無し)の読み方を決め、`FromDictionary` の既定値で表す。

### 手順 4: テストで確かめる(Linux)
```bash
dotnet test tests/Hikan.Core.Tests -c Release
```
- 新しい寸法・体積・型枠は**手計算の値**をテストに書く(コメントに計算式を残す)。
- 体積は式とは別の方法でも確かめる:
  - 直方体だけの構成 → スラブ分解(`HikanPartsTests.SlabVolume`)
  - 翼壁を含む構成 → 柱積分(`HikanWingTests.ColumnIntegral`、重なり体積も測れる)
- 既存テストの期待値が変わるときは、変わる理由を確かめてから直す(既定値の変更で崩れたテストは、目的に合わせて固定値の構成に変える)。

### 手順 5: AutoCAD 層・Dynamo 層を直してコンパイル検証する(Linux)
- Linux には Autodesk 製品が無いので、**Autodesk 公式 NuGet の参照アセンブリ**でコンパイルだけ確かめる(7.2 節)。
- 確認すること:
  - AutoCAD 層・Dynamo 層とも 0 エラー・0 警告
  - Dynamo の `[MultiReturn]` の辞書キーと `r["…"]` の代入キーが一致(コンパイラは検出しない)
  - `HIKAN_SelfTest` の全構成が整合性チェックを通る(SelfTest の `Case` を Core だけで評価する)
  - 整合性チェックの文が入力画面の該当欄に結び付く
  - `using` ディレクティブが無い

### 手順 6: 入力画面の模式図を確かめる(Linux)
- 模式図(`HikanSketch.cs`)は System.Drawing で描くので Linux では動かない。描画呼び出しを記録する代用品を差し込み、
  画像に書き出して文字の重なり・寸法線の位置を目で確かめる(7.3 節)。

### 手順 7: README・メモを更新してコミット・push
- README: 図・入力表・計算値・制約・「9. 既存 README.md との差分」。
- コミットして `git push origin main`。

### 手順 8: Windows 側で確認してもらう(4 章)
- 結果(SelfTest の行、エラー画面)を写真で返してもらい、NG があれば次の変更より先に直す。

## 4. Windows 側の手順

### 4.1 毎回の更新
1. **Civil 3D を閉じる**(読み込み中の DLL は上書きできない)。
2. リポジトリで `git pull`。
3. 参照 DLL のバージョンを検証する(Civil 3D を更新したときは必ず):
   ```powershell
   powershell -File scripts\verify-dll-versions.ps1
   ```
   AutoCAD 系 25.x・DynamoServices 3.3.x が OK であること。ProtoGeometry は参照していないので判定に使わない。
4. Visual Studio で `Hikan.sln` を開き、構成 **Release** でビルド(またはコマンド):
   ```powershell
   dotnet build src\Hikan.AutoCAD -c Release
   dotnet build src\Hikan.Dynamo -c Release
   ```
   `warning MSB3277`(Microsoft.VisualBasic / System.Drawing / WindowsBase)は無害(README 7 章)。

### 4.2 Civil 3D での確認
1. Civil 3D 2025 を起動し、`NETLOAD` で `src\Hikan.AutoCAD\bin\Release\net8.0-windows\Hikan.AutoCAD.dll` を読み込む。
2. `HIKAN_SelfTest` を実行し、**12 行すべてが OK** であることを確認する
   (函体のみ / 胸壁+しゃ水壁 / +翼壁 / +堤防保護部 / +門柱・操作台 / 胸壁を函体端に寄せる、の 6 構成 × 勾配 0・0.02)。
   各行の 体積・内空控除・エクステント・重心・XData・レイヤー・色 がすべて OK であること。
3. `HIKAN_Create` で入力画面を開き、既定値のまま作成して形を目で確かめる。変更した部材のタブを開き、模式図と入力欄も確かめる。
4. 結果をチャットに返す(NG・エラーは画面の写真)。

### 4.3 コマンド一覧

| コマンド | 内容 |
|---|---|
| `HIKAN_Create` | 入力画面 → 基準点(上流端 = 川裏端・底版下面・函体中心線)を指定 → ソリッド 1 個を作成 |
| `HIKAN_Action` | 作成済みのソリッドを選択 → 現在値で入力画面 → 同じ位置に作り直す |
| `-HIKAN_Create` / `-HIKAN_Action` | 上と同じことをコマンドラインで入力(スクリプト実行用) |
| `HIKAN_Query` | 選択したソリッドの諸元・数量・注記を表示 |
| `HIKAN_SelfTest` | 12 構成を作って検証し、消す |

### 4.4 入力画面のタブ
函体 / 川裏側胸壁 / 川表側胸壁 / 川裏側翼壁 / 川表側翼壁 / しゃ水壁 / 門柱・操作台 / 床掘り・色。
- 翼壁は内側に「基本条件 / 形状寸法 / 堤防保護部」、門柱・操作台は「基本条件 / 操作台 / 門柱」のタブを持つ。
- **確定**で全タブをまとめて整合性チェックし、エラーがあれば画面を閉じずに一覧・タブの「●」・欄のアイコンで示す。
- 灰色の形式(翼壁の逆T型など、3 本柱、操作台の形式 1〜3・5・6)は未実装。

### 4.5 Dynamo
`Hikan.Dynamo.dll` を Dynamo に読み込むと `HikanNodes.Estimate` ノード(数量のみ、モデルは作らない)が使える。
引数は入力画面と同じ項目、出力は日本語のキー(`コンクリート総計_m3` など)。

## 5. 形状の決め事(確認済み)

| 部材 | 決め事 |
|---|---|
| 座標 | X = 横断(下流を見て右が +)、Y = 延長(上流 = 川裏 → 下流 = 川表が +)、Z = 上。基準点 = 上流端・底版下面・函体中心線。**敷高 = 基準点 + 底版厚** |
| 胸壁 | 函体の左右側面に付く逆T字擁壁(左右同一)。位置は川裏函体端からたて壁の軸まで。底版上面 = 敷高、**左右の底版は函体の下でつながる**。必ず設置 |
| しゃ水壁 | 函体外周に全周一律(下方にも)張り出すカラー。延長を枚数で等分した各区間の中央 |
| 翼壁 | 左右の側壁 + 底版の U 字 3 面張り水路。底版上面 = 敷高。開き角は内空幅と端部の水路幅の差で決まる。必ず設置。形式は U 型のみ |
| 堤防保護部 | 翼壁端部から左右へ張り出す逆T字擁壁(X4 / L3 / L2 / L4)。底版 = 翼壁の底版。**Y3 = H1 − 敷高**(自動) |
| 門柱 | 函体の側壁の上に立つ L 字の柱 2 本(切欠き = ゲート溝、横方向壁は川裏側)。**胸壁の底版の上面から立ち**、Y2 もそこから。**背面 = 川表側胸壁のたて壁の背面**(位置は入力しない)。ハンチ H2 は縦方向壁(川表側の柱)の内面 |
| 操作台 | 両柱にまたがる版。X1 = X4 + X5 + 2·X3、X2 = B + 2·(X7 + X8) + 2·X6(1 mm を超えるとエラー)。管理橋ありなら川裏側の端に桁受けの切欠き(W1・W2・H1) |
| 土留壁(川表) | 門柱の間、下端 = 頂版上面、背面 = 門柱の背面、厚さ = X5、高さ WH。上端は川表側胸壁のたて壁の天端以上 |
| 土留壁(川裏) | 川裏側胸壁のたて壁の間、下端 = 頂版上面、背面 = 川裏側胸壁のたて壁の背面、高さ・厚さを入力。上端は川裏側胸壁のたて壁の天端以上 |
| 重なり | 部材の重なりは許し、ソリッドは一体化、体積は 1 回だけ数える。数量では先に作る部材に含める |
| 床掘り | 水平床掘りの概算。上部工(門柱・操作台・土留壁)は平面範囲に含めず、埋戻しの控除は現地盤より下だけ |

## 6. これまでに起きた問題と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| 検証スクリプトで ProtoGeometry が NG | ProtoGeometry は Dynamo と別のバージョン体系(3.0.x) | 判定から外した(参照もしていない) |
| ビルドで `warning MSB3277` が 3 件 | AutoCAD 側の参照と net8.0 参照パックの食い違い | 無害。生成 DLL の参照に含まれないことを確認済み |
| Civil 3D で「川裏側翼壁と川裏側胸壁左底版が干渉」エラー | 部材の重なりを入力エラーにしていた | 重なりを許し、体積を厳密に差し引く方式に変更 |
| 胸壁の形が 3 回違った | 文書に規定が無い部材を推測で作った | 以後、実装前に図で確認する |
| 埋戻しの控除で土留壁を二重に数えた | 上部工の地下部分の計算漏れ | 地上に出た部分を引く方式に変更(テストで検出) |
| Linux の作業用フォルダが消えた | セッションが変わると消える | 検証用プロジェクトを作り直す(7 章) |

<!-- dyncheck.csproj -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework><ImplicitUsings>disable</ImplicitUsings><Nullable>disable</Nullable>

## 8. 規約(CLAUDE.md / CLAUDE.PRIVATE.md より、作業中に毎回守ること)

- `using` ディレクティブを書かない(完全修飾名)。単位はメートルのみ(mm を混ぜない)。Z は上向き。
- ソリッドは最後に 1 個にまとめる(BoolUnite / BoolSubtract)。AutoCAD 本体 DLL は `<Private>False</Private>`。
- パラメータを決めるときは複数案と推奨案を示す。パラメータ表は「英語名 / 日本語名 / 単位 / デフォルト値 / 範囲」。
- 派生量には信頼度(確定 / 概算 / 推定)を付ける。
- 整合性チェックの許容誤差は 1 mm(0.001 m)。不一致ならエラーで止め、作り直さない。
- 回答・コメント・コミットメッセージは日本語。
