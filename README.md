# 樋管(ボックスカルバート型)パラメトリックモデル + 数量

『土木構造物設計マニュアル(案)－樋門編－(平成13年12月)』に基づく場所打ち鉄筋コンクリート樋管の
**函体(頂版・側壁・底版)+ 胸壁 + しゃ水壁 + 翼壁(+ 堤防保護部)+ 門柱・ゲート操作台**の 3D モデル(Solid3d 1個)生成と、
ジオメトリから確定的に出せる数量の計算を行う DLL 群。単位はメートル統一。

> **状態**: Core(ジオメトリ・整合性・数量)は **xunit 148 ケース全合格**。
> 函体のみ(第1段階)と、胸壁・しゃ水壁・胸壁の位置指定(第2段階)は Civil 3D 2025 実機の `HIKAN_SelfTest` で受入済み。
> 翼壁(U 字の 3 面張り水路)と入力画面は実機未確認。
> **参照DLLバージョンは 2026-10-07 に Civil 3D 2025 実機で検証済み**(§2 の表)。
> AutoCAD / Dynamo 層は Autodesk 公式 NuGet の参照アセンブリに対して **コンパイル検証済み**(0 エラー・0 警告)。
> 残るは実機での `HIKAN_SelfTest` の通過確認。

## 1. 概略図

```
   断面(XZ 平面)                               延長方向(+Y = 上流 → 下流)
   ┌─────────────────┐  ← 頂版厚              ┌──────────────────────┐
   │ ╔═════════════╗ │                        │                      │  ← 土かぶり
   │ ║             ║ │                        │  ╔════════════════╗  │
   │ ║  内空 B × H ║ │  ← 側壁厚(両側)       │  ║                ║  │
   │ ║             ║ │                        │  ╚════════════════╝  │
   │ ╚═════════════╝ │                        └──────────────────────┘
   └─────────────────┘  ← 底版厚               ├── 函体延長 L(斜距離)──┤
   ├─ 外形幅 B_out ──┤                         底版勾配 i で下流が落差ぶん下がる
   ●(0,0) = 底版下面 かつ 函体中心線

        +Z (鉛直上向き)
         │
         │     X = 横断方向。X = 0 が函体中心線(左右対称軸)。下流を向いて右が +X。
   基準点 ●────── +Y (施設延長方向。上流 → 下流)
        ╱        Y = X × Z の右手系。
      +X
   基準点 (base_x, base_y, base_z) = 上流端・底版下面・函体中心線上の点。
   底版勾配の回転軸もこの点を通る X 軸なので、上流端の高さが不動点になる。
```

生成手順: **部材ごとに 断面ポリライン → Region → Extrude で中実プリズムを作り、`BoolUnite` で合成
→ 最後に内空プリズムを 1 回だけ `BoolSubtract`** → X 軸まわり +90 度回転 → 基準点へ平行移動 → 底版勾配の回転。

薄いシェル同士を同一平面でブーリアンしないので、部材を増やしても退化しにくい。
合成は ModelSpace に追加したあと **DB 常駐のまま**行う(非常駐 Solid3d のブーリアンは環境によって拒否されることがあるため)。
途中で失敗しても `tr.Commit()` に到達しないので図面には何も残らない。

### 部材の構成(仮定)

参照文書には胸壁・しゃ水壁の寸法・張出し量・設置位置の規定が**一切ない**。
「全部材が等厚矩形」(基準の形状単純化方針)だけを根拠に、以下の形状を仮定している。

| 部材 | モデル | 位置 |
|---|---|---|
| 函体 | 外形 `B_out × H_out` の中実プリズム | `S ∈ [0, L]` |
| 川裏側胸壁 たて壁 | 函体方向に垂直な板。函体の**左右側面にそれぞれ**接して外側へ張出し長 `Lw` だけ張り出す。底版上面(= 函体の敷高)から立ち上がる | `S ∈ [d − 厚/2, d + 厚/2]`(`d` = 軸位置) |
| 川裏側胸壁 底版 | たて壁と同じ X 範囲。**上面を函体の敷高(内空底面 `Z = 底版厚`)にそろえる**。下面は 敷高 − 底版厚 | つま先版は川裏側、かかと版は函体中央側 |
| 川表側胸壁 | 同じ構成。川裏側と**別寸法**にできる | つま先版は川表側、かかと版は函体中央側 |
| しゃ水壁 | 函体外周に**全周一律**(下方にも)張り出すカラー。枚数 0 で設置しない | 函体延長を枚数で等分した各区間の中央 |
| 翼壁 | 左右の側壁と底版が一体の U 字の 3 面張り水路。八の字に開き、側壁の天端は函体から離れるほど下がる(§1 の「翼壁」) | 川裏 `S ∈ [−翼壁長, 0]` / 川表 `S ∈ [L, L + 翼壁長]` |
| 門柱・操作台 | 函体の左右の側壁の上に立つ門柱 2 本 + 両柱にまたがる操作台の版(§1 の「門柱・ゲート操作台」) | 門柱 `S ∈ [d − Wc/2, d + Wc/2]` |
| 内空 | `B × H` の中実プリズム(控除) | 函体のみ `S ∈ [0, L]` |

`S` は基準点(上流端)からの下流向き距離。

```
【胸壁の断面(XZ・下流を見る)】               【側面(YZ・片側)】

  ┌───┐                  ┌───┐  ← たて壁            ┌──┐  ← たて壁(厚 t)
  │   │ ┌──────────────┐ │   │                       │  │
  │   │ │ ╔══════════╗ │ │   │               ┌───────┴──┴───────┐ ← 底版上面 = 敷高
  │   │ │ ║   内空   ║ │ │   │               └────── 底版 ──────┘
  ├───┤ │ ╚══════════╝ │ ├───┤ ← 敷高         ├つま先┤      ├かかと┤
  └───┘ └──────────────┘ └───┘ ← 底版(上面 = 敷高、厚 tf)
 ──────────────────────────────── Z=0
  ├Lw─┤ ├──── 函体 ─────┤ ├Lw─┤   左右は同一形状(中心線で鏡映)
```

**上流端を川裏**とする(排水樋管の向き)。胸壁の函体方向の位置は、川裏側・川表側とも
**川裏函体端からたて壁の軸(厚さの中心)までの距離 `d`** で指定する(底版下面に沿う斜距離)。

```
【平面(上から)】
 川裏端                                                         川表端
  S=0                                                             S=L
   ├──── d(川裏側)┤
   ┌────────────┬─┬──────────────────────────────┬─┬────────────┐
   │            │┃│          函  体               │┃│            │
   └────────────┴─┴──────────────────────────────┴─┴────────────┘
                 ↑ たて壁の軸(厚さの中心)          ↑
   ├──────────────────── d(川表側)──────────────┤
```

たて壁は `d ± 厚/2` が函体延長 `0〜L` に収まる必要がある(はみ出すと函体側面に全厚で付かない)。
函体端に面一で置くなら、川裏側は `d = 厚/2`、川表側は `d = L − 厚/2`。

**左右の胸壁は同一形状**で、入力は片側分(7 項目)だけ。
**底版上面は函体の敷高(内空底面)にそろえる**ので、根入れ深さは入力しない(底版下面 = 敷高 − 底版厚。
底版厚を函体の底版厚と同じにすれば底版下面は `Z = 0`)。たて壁は敷高から天端まで立ち上がる。中心線 `X = 0` について鏡映して 2 基生成する。
胸壁は函体と**側面で接するだけで重ならない**(函体の上は跨がない)ので、体積の重なり補正は不要。
つま先版長またはかかと版長を 0 にすれば **L 字**になる(切替フラグは持たない)。

### 翼壁

左右の側壁と、その間をつなぐ底版(水路床)が一体になった **U 字の 3 面張り水路**で、函体端から外へ伸びる。
左右の側壁は同一形状(入力は 1 端あたり 6 項目)、川裏側・川表側は別寸法。

```
【平面(上から)・川表側の例】
   ──── 函 体 ────┐ ┌──────────────────────────────┐   ← 始端・終端とも函体端と平行に切る
                  │ │▓▓▓▓▓▓▓ 側壁(右) ▓▓▓▓▓▓▓▓▓▓▓▓▓│      (函体端面と隙間なく接する)
     内空 B       │ │        底 版(水路床)         │
                  │ │▓▓▓▓▓▓▓ 側壁(左) ▓▓▓▓▓▓▓▓▓▓▓▓▓│
                  │ └──────────────────────────────┘
                    ├──── 翼壁長 La(函体軸方向)────┤
     側壁の内面は函体端で内空側面(X = ±B/2)、翼壁端部で X = ±W/2

【側面(側壁に沿って)】                       【断面(翼壁の位置で見る)】
  H0 ┌─────╲_____                              ┌──┐                    ┌──┐ ← 側壁(厚 ts)
     │           ╲________  ← 天端は直線で下がる │  │       水 路        │  │
     │   側 壁            │ H1                   │  └────────────────────┘  │ ← 底版上面 = 函体の敷高
 ────┴────────────────────┴── 底版上面(= 敷高)  └────────── 底 版 ─────────┘ ← 底版厚 tf
     └──────── 底 版 ─────┘                          ├── 水路幅(B → W)──┤
                                                     底版は側壁の外面まで(U 字)
```

- **底版上面は函体の敷高(内空底面)に合わせる**ので、水路床が函体の内空と段差なくつながる。
  底版厚を函体の底版厚と同じにすれば、底版下面も函体の底版下面(Z = 0)とそろう。底版は側壁の外面まで(張出しなし)。
- **開き角は入力しない**。函体に取り付く部分の水路幅(= 内空幅 `B`)と**翼壁端部の水路幅 `W`**(左右の側壁内面間)の差から
  `tanθ = (W − B) / (2 × La)` で決まる。`W = B` で平行。底版も同じく台形に広がる。開き角は派生量として出力する。
- 翼壁長 `La` は函体端から翼壁端部までの**函体軸方向**の長さ。側壁厚は**壁面に直交**する方向で測る。
- 側壁の天端は函体端で `H0`、翼壁端部で `H1`(どちらも函体底版下面 Z = 0 から)、間は直線。壁の厚さ方向には水平。
- 函体端近くに置いた胸壁の底版(つま先版)が函体端より外へ出て、翼壁の底版(厚い場合)と重なってもよい。
  重なった部分は `BoolUnite` で一体化し、体積の解析解では重なり(直方体と翼壁部材の共通部分。S 区間を折れ点で分けて
  シンプソン則で厳密に積分)を 1 回だけ差し引く。数量では**重なりを胸壁に含め、翼壁から差し引く**(部材別の合計が総量に一致する)。

### 門柱・ゲート操作台

函体の**左右の側壁の上に矩形の門柱を 1 本ずつ**立て(左右同一)、**両柱にまたがる操作台の版**を載せる。
ゲート溝(戸当り)・頂版の開口・ゲート設備・管理橋は作らない。既定は設置する(キーの無い旧図面は設置しない)。

```
【正面(下流を見る)】                               【側面】
 ┌───────────────────┐ ← 操作台(厚 td)              ├as┤      ├as┤
 └─┬──┬───────────┬──┬─┘                             ┌──────────────┐ ← 操作台
   │  │           │  │  ↑                            └──┬────────┬──┘
   │門│           │門│  Hc(門柱天端高 =                 │  門柱  │  Hc
   │柱│           │柱│     操作台下面、Z=0 から)         │        │
 ┌─┴──┴───────────┴──┴─┐ ← 頂版上面                ────┴────────┴──── 頂版上面
 │ ┌───────────────┐ │                                  ├── Wc ──┤
 │ │      内空      │ │                              d = 川裏函体端から門柱の中心まで
 │ └───────────────┘ │
 └───────────────────┘
   ├Tc┤ 門柱厚(内面 = 内空側面)        操作台は門柱の外面から左右に ax 張り出す
```

- 門柱は頂版上面から `Hc` まで。内面を函体の内空側面にそろえ、外向きに厚 `Tc`(側壁厚より厚ければ函体の外面より外へ出る)。
- 函体方向の位置は胸壁と同じく**川裏函体端から門柱の中心までの距離 `d`**。門柱は函体延長の中に収める。
- 操作台は `Hc` から厚 `td`。左右は門柱の外面から `ax`、前後は門柱の面から `as` 張り出す。函体端より外へ張り出してもよいが、
  その側の翼壁・堤防保護部の天端より高い所にあること。
- 門柱・操作台は他の部材と重ならない(整合性チェックで、しゃ水壁・胸壁のたて壁と函体方向に重なる配置を弾く)ので、体積は単純和。
- **床掘りの平面範囲には含めない**(操作台は高い所にあり、左右に張り出しても床掘りの底幅を広げない)。
  埋戻しから控除する地下占有体積には、**現地盤(頂版上面 + 土かぶり)より下の部分だけ**を含める。

### 堤防保護部(翼壁の付属)

翼壁の**端部から左右(堤防法線の方向)へ張り出す逆T字擁壁**。翼壁の「基本条件」で設置する/しないを選び、
設置する場合だけ寸法を入力する(既定は設置しない)。左右同一形状、川裏側・川表側は別寸法。
記号は手本の樋門設計ソフトの「形状寸法」画面に合わせている。

```
【平面(川表側の例、上が函体)】                       【側面(保護部を横から)】
            │ │  水路  │ │  ← 翼壁の側壁                     ┌──┐ ↑
┌────────╱ ╱            ╲ ╲────────┐ ┐                       │  │ Y3      翼壁 → 函体
│ かかと版│              │ かかと版 │ │L4                ┌──────┤  ├────────┐ ↓ ← 底版上面 = 敷高
├────────┤              ├────────┤ ┤                  └──────┴──┴────────┘
│▓たて壁▓│              │▓たて壁▓│ │L3                ├─ L2 ─┼ L3┼── L4 ──┤
├────────┴──────────────┴────────┤ ┤ ← 翼壁端部
│        つま先版(左右つながる)    │ │L2
└────────────────────────────────┘ ┘
├── X4 ──┤              ├── X4 ──┤   X4 は翼壁端部の側壁内面から外向き(側壁厚を含む)
```

- たて壁(厚 `L3`)は外側(函体から遠い側)の面を**翼壁端部にそろえ**、翼壁の側壁内面から外向きに `X4` まで張り出す。
- かかと版(`L4`)は函体側、つま先版(`L2`)は翼壁端部より外側へ伸び、**つま先版は水路床の下も含めて左右つながる**。
- 底版は**上面 = 敷高、厚さ = 翼壁の底版厚**(入力しない)。たて壁高 `Y3` は敷高から測る。
- たて壁・底版は翼壁の側壁・底版と重なる。重なりは `BoolUnite` で一体化し、体積の解析解では胸壁のときと同じ方法で 1 回だけ差し引く。
  数量では**堤防保護部を総量で数え、翼壁から重なりを差し引く**。堤防保護部の型枠は計上しない。
- 整合性チェック: たて壁厚は 0.40 m 以上・0.10 m ピッチ、`X4` > 側壁の横断方向の幅(側壁厚 / cosθ)、
  `L3 + L4` ≤ 翼壁長、八の字の場合は `(L3 + L4) × tanθ` ≤ 側壁の横断方向の幅(超えると函体側で側壁から離れる)、
  胸壁の底版と函体軸方向で重ならないこと(3 部材が重なると体積の解析解が崩れるため)。

翼壁は軸にそろった直方体ではないので、**平面形を鉛直に押し出したプリズム**と**側面形(台形)を横断方向に押し出したプリズム**の
**共通部分(`BoolIntersect`)**として作る。どちらも「断面ポリライン → Region → Extrude」で、構築座標から作図座標へは
鏡映を含まない剛体変換(`Matrix3d.AlignCoordinateSystem`)で移す。天端が水平なら側面プリズムは使わない。

体積は `側壁 = 2 × 厚 × 壁面長 × (平均天端高 − 底版上面高)`(壁面長 = `La / cosθ`)、
`底版 = 底版厚 × La × 平均全幅`(全幅 = 水路幅 + 2 × 側壁の横断方向の幅)。これを部材ごとのシンプソン積分(断面の幅と高さが S の 1 次式なので厳密)と突き合わせ、
さらに (U, S) の柱ごとに V 区間を厳密に重ね合わせる独立の数値積分で、合併体積が体積式と一致し、
**柱積分で測った部材の重なりが、既知の「しゃ水壁 ∩ 函体」と解析的に求めた「胸壁 ∩ 翼壁」の和に一致する**ことを確かめている。

## 3. AutoCAD / Civil 3D コマンド(`NETLOAD` で `Hikan.AutoCAD.dll` を読み込む)

| コマンド | 説明 |
|---|---|
| `HIKAN_Create` | **入力画面**でパラメータ入力 → 基準点を指定 → Solid3d 1個生成 → XData(`HIKAN_PARAM`)記録 → レイヤー「樋管函体」・色設定 |
| `HIKAN_Action` | 既存ソリッド選択 → XData から現在値を復元して**入力画面**を開く → 同位置再生成(基準点は変えない。旧ソリッドは消去、ハンドルは変わる) |
| `-HIKAN_Create` | `HIKAN_Create` のコマンドライン入力版(基準点 → 各値を順に入力)。スクリプト実行用 |
| `-HIKAN_Action` | `HIKAN_Action` のコマンドライン入力版。スクリプト実行用 |
| `HIKAN_Query` | XData 読取 → 諸元・派生量・数量を信頼度ラベル付きで出力 → 根拠不足項目の注記を出力 |
| `HIKAN_SelfTest` | 下記 12 ケースを生成 → 検証 → 消去 |

### 入力画面(`HIKAN_Create` / `HIKAN_Action`)

構造物ごとのタブを切り替えて入力する。各タブは左に**寸法記号つきの模式図**(形・比率は固定で、入力値には連動しない)、
右に入力欄(記号 / 名称 / 値 / 単位)と注記を並べる。入力項目と意味はコマンドライン入力と同じ。

| タブ | 入力欄(記号) |
|---|---|
| 函体 | B 内空幅 / H 内空高 / tw 側壁厚 / tt 頂版厚 / tb 底版厚 / L 函体延長(斜距離)/ i 底版勾配 / ブロック数 |
| 川裏側胸壁・川表側胸壁 | t たて壁厚 / d 軸位置 / Lw 張出し長 / Hc 天端高 / tf 底版厚(上面は敷高)/ Lt つま先版長 / Lh かかと版長 |
| 川裏側翼壁・川表側翼壁 | 内側のタブで切り替える。**基本条件**: 形式(U型のみ選択可。逆T型・U型張り出し・U型底版傾斜は今後対応のため灰色)/ 堤防保護部 設置する・設置しない。**形状寸法**: ts 側壁厚 / La 翼壁長 / W 端部の水路幅 / H0・H1 側壁の天端高(函体端・端部)/ tf 底版厚。**堤防保護部**(設置するときだけ表示): X4 張出し幅 / L3 たて壁厚 / Y3 たて壁高 / L2 つま先版長 / L4 かかと版長 |
| しゃ水壁 | Nc 枚数(0 で設置しない)/ tc 厚 / a 張出し量 |
| 門柱・操作台 | 設置する・設置しない / d 軸位置 / Tc 門柱厚 / Wc 門柱幅 / Hc 門柱天端高 / td 操作台厚 / ax 左右の張出し / as 前後の張出し |
| 床掘り・色 | Hs 土かぶり / m 床掘り余裕幅 / n 法勾配 / f 基礎材厚 / ソリッド色(ACI) |

- 胸壁・翼壁は必ず設置する。たて壁厚・側壁厚の既定値は 0.400 m で、0.40 m 未満(0 を含む)はエラー。
- しゃ水壁の枚数を 0 にすると、そのタブの他の欄は無効(灰色)になり、値は保持される。
- **確定**で全タブをまとめて整合性チェック(§5 と同じ `HikanValidator`)する。エラーがあれば画面を閉じず、
  画面下の一覧に表示し、該当タブに「●」、該当欄にエラーアイコン(マウスを乗せると理由)を付けて最初のエラーへ移動する。
  一覧の行を選ぶとその欄へ移動する。部材どうしの干渉など欄を 1 つに絞れないエラーは、タブだけを示す。
- 数値は半角・全角どちらでも入力できる。桁区切りのカンマは受け付けない(`1,5` を 15 と読まないため)。
- 基準点は画面では扱わない(`HIKAN_Create` は画面を閉じたあとにコマンドラインで指定、`HIKAN_Action` は元の位置のまま)。

`HIKAN_SelfTest` の 12 ケース(いずれも 頂版厚 0.4 / 底版厚 0.6、基準点 (1.5, 2.5, 0.75)):
函体のみ / 胸壁+しゃ水壁 / 胸壁+しゃ水壁+翼壁 / それに堤防保護部を付けたもの / それに門柱・操作台を付けたもの /
胸壁を函体端に寄せて翼壁と重なる配置 の 6 構成 × 勾配 0・0.02。
段階ごとに分けてあるので、どの段階の部材で落ちたか切り分けられる。
「函体のみ」のケースは胸壁・翼壁の厚を 0 にしており、旧版で作った図面(厚 0 = 設置なし)を読み直す場合の互換確認を兼ねる。
胸壁の底版上面と翼壁の底版上面はどちらも敷高なので、「函体端に寄せる」ケースでは胸壁を寄せるだけで両者が重なる。
胸壁は川裏側(軸位置 2.0・たて壁厚 0.5・張出し 1.5・天端 4.0)と川表側(17.5・0.6・2.0・4.5)で**別寸法**にしてあり、
川裏・川表の取り違えを検出できる。どちらも函体端から離して置き、軸位置の指定が効いていることも確かめる。
翼壁は川裏側を八の字(内空幅 2.0 → 端部 3.0、翼壁長 3.0、天端 3.5 → 2.0)、川表側を平行(翼壁長 4.0、天端 4.0 → 2.5、底版厚 0.8 で
底版下面が Z = 0 より下がる)にして、
斜めに開く部材と天端が傾く部材(`BoolIntersect` で作る)の両方を確かめる。
門柱・操作台は川表側の函体端に寄せ(d 19.5 / Tc 0.6 / Wc 1.0 / Hc 7.0 / td 0.4 / ax 0.5 / as 0.5)、
操作台が函体端より外(翼壁の上)へ張り出す形と、門柱が函体の外面より外へ出る形(門柱厚 0.6 > 側壁厚 0.4)を確かめる。
堤防保護部は川裏側(X4 1.2 / L3 0.4 / Y3 2.0 / L2 0.5 / L4 1.0、八の字の翼壁に付く)と
川表側(X4 1.5 / L3 0.5 / Y3 2.5 / L2 0.6 / L4 1.2、平行の翼壁に付く)で別寸法にしてある。

`HIKAN_SelfTest` が確認すること:

1. **体積** = (外形 − 内空) × L(±0.001 m3)
2. **内空控除** = 体積が外形プリズム体積より小さい(内空が実際に抜けている)
3. **3軸エクステント** = `HikanGeometry.ExpectedExtents` と一致(押出し方向・回転符号・基準点オフセットの検査)
4. **3成分重心** = `HikanGeometry.ExpectedCentroid` と一致
5. XData 往復(全キー一致)・レイヤー名・色

**2 の「内空控除」は外形エンベロープ(コンクリート + 内空)との比較**で判定する。

**4 が必須である理由**: 体積と 3 軸エクステントは**断面の上下反転では変化しない**(頂版厚 ≠ 底版厚 の函体を
上下反転してもバウンディングボックスと体積は完全に一致する)。回転符号を誤ったときに起きるのがまさにこの誤りなので、
重心の照合がないと検出できない。SelfTest が頂版厚 ≠ 底版厚 かつ基準点 Z ≠ 0 で走るのも同じ理由。

生成時検証は `tr.Commit()` の前に実行するので、**不一致の場合は図面に何も残らない**。

および**胸壁・しゃ水壁の寸法・張出し量・設置位置**の算定式や標準値表はルート直下の参照文書(いずれも要約)に
記載がないため、すべて入力パラメータとしている。

**胸壁・翼壁は必ず設置する**(既定値 たて壁厚・側壁厚 0.400 m、0.40 m 未満は入力エラー)。しゃ水壁の既定値は 0 枚(設置しない)。
旧版で作った図面の XData は、胸壁・翼壁のキーが無い場合や厚が 0 の場合に**「設置なし」として読み込む**
(`HIKAN_Query` はそのまま使える)。`HIKAN_Action` で編集すると新規入力と同じ検査になるので、厚 0.40 m 以上を入れて設置する。
旧版の胸壁の根入れ深さ(`*_breast_embedment`)のキーは読み込み時に無視し、底版上面を敷高に置き直す。

## 7. ビルド方法

`Hikan.Core` と `Hikan.Core.Tests` は AutoCAD 非依存(`net8.0`)なので Linux / WSL でもテストまで実行できる。

```bash
dotnet test tests/Hikan.Core.Tests -c Release
```

AutoCAD / Dynamo 層は Autodesk 製品のインストール先を参照するため Windows 側でビルドする。

```powershell
# 1. 参照DLLバージョン検証(不一致ならここで停止)
powershell -File scripts\verify-dll-versions.ps1
# 2. AutoCAD / Dynamo 層(インストール先が異なる場合は -p:AcadDir / -p:DynamoCoreDir で上書き)
dotnet build src\Hikan.AutoCAD -c Release
dotnet build src\Hikan.Dynamo -c Release
```

配布時は `Hikan.AutoCAD.dll` / `Hikan.Dynamo.dll` と `Hikan.Core.dll` を同じフォルダに置く(AutoCAD 本体 DLL は含めない)。

### ビルド時に出る `warning MSB3277` について(無害)

`Hikan.AutoCAD` のビルドで `Microsoft.VisualBasic` / `System.Drawing` / `WindowsBase` の 3 件の
`MSB3277`(異なるバージョン間で解決できない競合)が出るが、**対処不要**。

発生源は AutoCAD 側で、`AcMgd.dll` などがこれらの新しいバージョンに依存しているのに対し、
net8.0 の参照パックが公開しているのは互換ファサード側、という食い違いによる。
C# コンパイラは実際に型を使ったアセンブリしか参照に残さないため、**生成される
`Hikan.AutoCAD.dll` の参照は `System.Runtime` / `System.Collections` / `accoremgd` / `Acdbmgd` のみ**で、
競合している 3 つは 1 つも含まれない(メタデータの AssemblyRef を読んで確認済み)。
`<Private>False</Private>` により配布物にも同梱されず、実行時は AutoCAD が自身のコピーを読む。

`<MSBuildWarningsAsMessages>MSB3277</MSBuildWarningsAsMessages>` で抑制できるが、将来 `System.Drawing`
などを実際に使う参照を追加したときに本物の競合を見逃すため、既定では抑制していない。

## 8. 規約・制約

- `using` ディレクティブ不使用(完全修飾名)、mm 不使用(メートル統一)、Z は上向き、AutoCAD 系 DLL は Private=False。
- 整合性チェック違反は `HikanValidationException` でエラー停止し、再生成しない(許容誤差 1 mm = 0.001 m)。
  長さ・面積・体積で許容誤差の定数を分けている。
- **前提**: ボックスカルバート型 **1 連**の**函体 + 胸壁 + しゃ水壁 + 翼壁(+ 堤防保護部)+ 門柱・ゲート操作台**。
  門柱・操作台はゲート溝(戸当り)・頂版の開口・ゲート設備・管理橋を含まない単純な柱と版。翼壁の形式は U 型のみ
  (逆T型・U型張り出し・U型底版傾斜は入力画面に表示だけしている)。翼壁天端の折れ(手本の B1・B2)と照査位置 P1、
  断面照査の適用基準・鉄筋量は扱わない。水叩き・護床工・ゲート設備・管理橋は対象外。
- **既知の制約(胸壁・しゃ水壁の形状)**: 参照文書に寸法・張出し量・設置位置の規定がないため、
  §1 の「部材の構成(仮定)」に書いた形状を仮定している。特に**しゃ水壁は全周一律(下方にも)張り出すカラー**として
  モデル化しており、側方・上方のみに張り出す形式が正しい場合は `HikanGeometry.GetParts` の 1 行で変えられる。
- **既知の制約(胸壁の数量区分)**: 函体と胸壁の打継ぎ・目地の扱いは数量に反映していない。
  たて壁の函体側端面は、函体より上に出る部分も含めて型枠を計上していない。
- **既知の制約(胸壁の位置)**: たて壁は軸位置 `d ± 厚/2` が函体延長の中に収まる範囲でのみ置ける。
  上流端 = 川裏で固定(取水樋管のように下流端が川裏の構成には未対応)。左右で寸法が異なる胸壁には対応していない。
- **既知の制約(胸壁の接合)**: 胸壁は函体側面と面で接して `BoolUnite` で一体化する。函体の上は跨がない。
- **既知の制約(翼壁)**: 翼壁は開く向き(端部水路幅 ≥ 内空幅)のみ。
  翼壁の始端・終端は函体端と平行な面で切る(壁に直角な端面ではない)。翼壁と函体・胸壁の打継ぎ・目地は数量に反映していない。
  天端の傾斜は函体軸方向にだけ付く(壁の厚さ方向は水平)。底版上面は函体の敷高に固定(段差は付けられない)。
  底版の側壁外への張出しは無い(U 字)。護床工は対象外。
- **既知の制約(底版勾配)**: 勾配は押出し後の剛体回転で表現するため、**上下流の端面が鉛直にならない**。
  勾配が 1/100 程度までなら実用上の影響は小さい。回転は体積を保存するのでコンクリート数量には影響しない。
  端面を鉛直に保つには**せん断変換**(`z' = z + i·y`、行列式 1 なので同じく体積保存)が幾何的に正しいが、
  `Solid3d.TransformBy` に非直交行列を渡したときの ACIS の挙動が未確認のため第2段階の課題とする。
- **既知の制約(ブロック割)**: `block_count` は形状に反映せず数量の按分表示のみ。継手の目地幅は控除していない。
- **既知の制約(型枠)**: 面積の内訳のみを出し合計は出さない。頂版上面・底版下面は計上せず、端面は両端に型枠が立つ前提。
  支保工は算定しない。どの面を計上するかは実務判断のため、文書に根拠がない合計の自動化はしない。
- **既知の制約(床掘り)**: 勾配 0 の水平床掘りとして概算する。土留め工(自立・切梁)を用いる場合は鉛直掘削になり
  角錐台の式が成立しない。土量換算係数(ほぐし・締固め)、流用土/購入土の区分、裏込め材の区分は未対応。
- **対象外**(第4段階以降): 門柱・ゲート操作台、鉄筋・ユニット鉄筋、目地・止水板、足場・支保工、基礎杭、
  残土処理、グラウトホール、管理橋、ゲート設備、プレキャスト函渠、円形管(樋管)、多連ボックス、歩掛・金額。
- **参照文書の根拠不足**: ルート直下の参照文書 4 本はいずれも**原典ではなく要約**で、
  『数量集計表様式(樋門・樋管)』には本体工のコンクリート・型枠・鉄筋の**細別名・規格・積算単位が収録されていない**。
  本 DLL の出力は自前の項目名・単位による数量であり、数量集計表の様式にそのまま貼れる保証はない。
  様式に合わせるには原典 Excel(平成20年4月版)が必要。
- 座標系は `CLAUDE.PRIVATE.md` §2.2 の定義に従う(上記 1. と同一)。同表には X 軸の定義行が欠落し、
  Y 行の備考が「法線平行方向」のままだったため、X 軸の行の追加と Y 行の「法線直交方向」への修正を行っている。
